# AGENTS.md

Kotlin Android app, single `:app` module, package `com.example.myapplication`. A Grade-3 oral arithmetic (口算) trainer: `nav_transform` (start destination) hosts the quiz UI, `nav_review` (查看错题) is reachable from it, plus `nav_history` (历史错题), `nav_achievements` (成就) and `nav_settings` (设置, music + account). All other template fragments were removed — no bottom nav, no navigation drawer, single-screen app.

## Commands (Windows)

- Build: `.\gradlew.bat assembleDebug`
- Install on device/emulator: `.\gradlew.bat installDebug`
- Unit tests (host JVM): `.\gradlew.bat test` — all real tests live in `app/src/test/.../arithmetic/` (+ `audio/PlaybackRulesTest`); the sole `app/src/androidTest/` file is the template `ExampleInstrumentedTest` and needs a device/emulator. Run one class with `.\gradlew.bat test --tests "com.example.myapplication.arithmetic.RewardRulesTest"`
- Lint: `.\gradlew.bat lint`

## Toolchain (agents will guess these wrong)

- No `java` on PATH; `JAVA_HOME` must be set explicitly, e.g. `$env:JAVA_HOME = "C:\Program Files\Java\latest\jdk-27"` before every `gradlew.bat` invocation in PowerShell.
- `.\gradlew.bat test` can fail at the worker-JVM bootstrap with `ClassNotFoundException: Files\Java\jdk-27\bin;...` if `$env:Path` contains a stray double-quoted JDK entry. Sanitize first: `$env:Path = (($env:Path -split ';') | Where-Object { $_ -notmatch '^"' -and $_ -ne '' }) -join ';'` then `.\gradlew.bat --stop` and rerun.
- AGP 9.4.1 + Gradle 9.6.0, running on JDK 25 auto-provisioned by the foojay resolver (`gradle/gradle-daemon-jvm.properties`). Don't assume a local JDK.
- AGP 9 DSL — do not revert to old syntax:
  - `compileSdk { version = release(37) }` (`app/build.gradle.kts:7`)
  - `optimization { enable = false }` replaces `isMinifyEnabled` (R8 is off in release).
- Keep rules go in `app/src/main/keepRules/` — AGP auto-combines that whole directory; there is no `proguard-rules.pro`.
- `org.gradle.configuration-cache=true` is set; keep build scripts config-cache compatible.
- `local.properties` sets `sdk.dir=D:\android_sdk` and is gitignored (machine-specific). Builds fail if it's missing.
- Java 11 source/target compatibility regardless of toolchain version.

## App structure

- View Binding is enabled; `MainActivity` and all fragments use generated `*Binding` classes.
- One nav graph (`res/navigation/mobile_navigation.xml`, start destination `nav_transform`) with the quiz plus four non-top-level pages — `nav_review` (查看错题), `nav_history` (历史错题), `nav_achievements` (成就, shows 👑 crown count from the `rewards` table via `AchievementsFragment`/`AchievementsViewModel`) and `nav_settings` (设置, hosts all music settings + account management via `SettingsFragment`) — navigated via `navigate(...)`. No bottom nav / drawer / menus; `MainActivity` hides the toolbar (`setDisplayShowTitleEnabled(false)` + `visibility="gone"` in all three `app_bar_main.xml` variants) for fullscreen and enables edge-to-edge immersive mode with gesture navigation (`WindowCompat.setDecorFitsSystemWindows(false)` + `WindowInsetsControllerCompat.hide(systemBars)` with `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`); back navigation relies on the system back gesture.
- The quiz lives in `ui/arithmetic/` (`ArithmeticFragment` + `ArithmeticViewModel`, a 3-phase setup/quiz/result state machine). Rounds are always mixed operations (加减乘除, no operation picker). Add/sub operands are ≤100, sum ≤100, subtraction non-negative; multiplication is 1..20 × 1..10 (both operand orders legal, per product spec). Background music: `MusicPlayer` (built-in 10-song store in `res/raw/music_*.mp3`, CC0 from meme2-cmd2/CC0-Music "Ambient, Calm & Meditative"). Three playback modes, chosen via `btn_mode_single|list|shuffle` on the settings page (`fragment_settings.xml`/`SettingsFragment`; pure-Kotlin `MusicMode` + `PlaybackRules` in `audio/PlaybackRules.kt`, unit-tested in `PlaybackRulesTest`, persisted as int `bg_music_mode`: 0=单曲循环, 1=列表循环, 2=随机不重复 — no backend/template loop categories). A settings-page `switch_music` toggle (default off, persisted in `app_prefs`; created as an `AppCompatCheckBox` — never `MaterialSwitch`, which NPE-crashes on measure) calls `MusicPlayer.setEnabled`; the home page has no music controls — tapping the home avatar (`img_current_avatar`) toggles music on/off the same way (with a toast). **`MainActivity.onResume/onPause`** starts when enabled and pauses when the app leaves the foreground — music keeps playing across all nav destinations. While enabled the home avatar rotates continuously (a `ValueAnimator`/`ObjectAnimator` spin ~6s/rev, driven by a `MusicPlayer.addPlayStateListener` callback) and returns upright when music stops/pauses; the guest default avatar also spins so the effect is always visible. Setup only picks the question count (10/20/50/100); the selected count button is styled purple bg + white text via `backgroundTintList`/`setTextColor` in the `questionCount` observer (restore default colors with the captured `defaultCountTextColors`, never pass `null` to `setTextColor` — AOSP NPEs and the app crashes on launch). Setup also shows a random welcome line (from `setup_welcome` string-array, picked in `setupSetup`) and four reward chips (小花/红心/蓝宝石/皇冠 via `text_setup_yellow_flower|heart|gem|crown` inside a `MaterialCardView`, each rendered on one line as "emoji ×N" via `setup_*_chip` strings, refreshed by `refreshRewardCounts()` whenever the phase returns to SETUP). The setup page is a `ScrollView` (`phase_setup`) with a gradient header (`bg_header_gradient`); nav buttons (开始练习/错题重练/查看错题/查看历史错题/查看成就) share the `Button.SetupNav` style (rounded 16dp filled), the count picker uses `Button.CountOutlined` (rounded 12dp outlined). Theme is Material Components (not M3) with a modern palette in `colors.xml` + dark overrides in `values-night/colors.xml` (`color_background`/`color_surface`/`color_input_bg` via `bg_input_rounded` are the light/dark-aware surfaces). Answering advances on the main thread: a correct answer jumps to the next question immediately; a wrong answer shows feedback for ~0.5s before advancing (both via a `Handler`-posted callback); a `退出` button in the quiz header calls `backToSetup()`. **暂停**: a `btn_pause` header button (pause only allowed in QUIZ) calls `ViewModel.pause()` — stops the timer, removes the `advanceCallback`, records `pauseStartTime` and sets `paused`; `onDigit`/`onBackspace`/`onSubmit` all early-return while `paused`. The full-screen `phase_pause` overlay (dim + on API≥31 `phaseQuiz` gets `RenderEffect.createBlurEffect(16f,16f)` applied/removed in the `paused` observer; `null` below API 31) has `btn_resume` (restores `_paused=false`, adds `(System.currentTimeMillis()-pauseStartTime)` to `startTime` so paused time isn't counted, restarts `timerCallback`, and re-posts `advanceCallback` if feedback pending) and `btn_pause_exit` (also `backToSetup()`). System back while paused exits the activity (same as un-paused quiz). **无限模式**: a `btn_endless` setup button (无限挑战, placed above `btn_start`) calls `startEndless()` — `begin(listOf(generator.generateMixed(1).first()), endless=true)`; answering correctly swaps in a fresh single-question list and never ends the round; the first wrong answer ends it via `endEndlessRound()` (stops timer, settles rewards, shows RESULT). That ending wrong answer stays in the result 错题回顾 but is **not** written to the DB (`recordWrong` is skipped while `_endless`). Rewards accumulate once per 100-cycle via `EndlessRewardRules` (pure Kotlin, unit-tested in `EndlessRewardRulesTest`): each completed 100 correct = one 👑 (`crownCountFor` = n/100), and within every cycle the +10/+20/+50 correct milestones grant one 🌸/❤️/💎 (`flowerCountFor` = (n-10)/100+1 when n≥10, plus `heartCountFor`, `sapphireCountFor`); `rewardCounts(n)` returns per-type totals, each inserted via `repository.insertReward`. Result page for endless shows `endless_score` (答对 N 题), a multi-item `result_reward_endless` summary (e.g. 🌸×2 ❤️×1 💎×1 👑×1), and the same 称号/错题回顾/用时 lines; records (`updateRecord`), redo and 错题本 entry are skipped. Quiz header title becomes `quiz_endless`, progress shows `endless_progress` (已答对 N 题); timer/combo/energy/pause/blur all work unchanged. Fun features: `combo` LiveData (≥2 shows "🔥 已连对 N 题", resets on wrong answer, `bestCombo` tracked privately); a one-second `elapsedSeconds` ticker while in QUIZ (`timerCallback`, stopped by `stopTimer()`); correct answer plays a high beep (`ToneGenerator`) + scale-bounce on `text_question`, wrong answer plays a low beep + shake on `text_input` (double-pulse vibration when combo broke at ≥3). **能量槽** (`EnergyBarView`, top of `phase_quiz`): `energy` LiveData (0..100) resets to 0 each round, +15 per correct (`EnergyRules.afterGain`), −2 per second while in QUIZ (`EnergyRules.afterDrain` in the 1s `timerCallback`); vibration on correct is energy-gated — none below 50, scaling tiers 50/70/90 via `EnergyRules.vibrationTierFor` (40ms/80amp → 80ms/160 → 120ms/255, `vibrateForEnergy()`); bar fill + color run a smooth ValueAnimator, 3-stop gradient 浅黄 `#FFF9C4` → 橙 `#FFB300` → 红 `#F44336`. A wrong answer resets energy to 0 (`_energy.value = 0f` in `onSubmit()`). `EnergyRules` is pure Kotlin, unit-tested in `EnergyRulesTest`. `TextCombo`/`text_quiz_timer` live between the quiz header row and the question. Do not re-add nav menus here.
- Pure Kotlin problem generation in `arithmetic/` (`ArithmeticProblemGenerator`, `Operation`, `ArithmeticQuestion`) — keep testable on the host JVM, no Android deps. `EndlessRewardRules` (pure Kotlin, unit-tested in `EndlessRewardRulesTest`) settles 无限模式 rewards from the final correct count (see the quiz bullet). `RewardRules` (also pure Kotlin, unit-tested in `RewardRulesTest`) decides rewards via `rewardForRound`: a perfectly answered *practice* round of 10/20/50/100 questions earns 小花/红心/蓝宝石/皇冠 respectively (`REWARD_QUESTION_COUNTS`, types `YELLOW_FLOWER`/`RED_HEART`/`SAPPHIRE`/`CROWN`, all stored in the `rewards` table; review rounds never earn rewards). `RewardRules` also maps crown counts to a level via `levelIndexForCrowns` (thresholds `CROWN_LEVEL_THRESHOLDS` = 0/1/3/6/10 → 青铜/白银/黄金/钻石/王者 from the `crown_level_names` string-array) and `nextLevelCrowns`. `ResultComment` (pure Kotlin, unit-tested in `ResultCommentTest`, takes an injected `Random`) picks a playful 称号 + 鼓励语 tiered by score ratio; the result page shows the title line, stars, and a reward badge (`text_result_reward`, color-coded per reward). Setup page shows all four reward count chips and the achievements page lists all four counts below the crown/level block.
- One-chance 错题重做: after a 50/100-question practice round with wrongs, `advance()` sets `_canRedo` (gated by `REDO_QUESTION_COUNTS`); the result-page `btn_redo_wrong` (label `btn_redo_result`) is shown only while `canRedo==true` and calls `startRoundRedo()` (rebuilds questions from this round's `_wrongProblems`, not the DB). `redoUsed` is set true right after `begin()` so a second chance is never offered. No reward for the redo; answering a redo question correctly deletes it from 错题本 via `repository.deleteWrong`.
- 错题 storage is split (DB v5): `wrong_problems` (查看错题, deletable — redo corrects delete/remove) and `wrong_history` (历史错题, append-only: every `recordWrong` also inserts a row into `wrong_history`, queried only via `fetchHistory`). `HistoryFragment` (`nav_history`, label `history_title`) is a read-only copy of `ReviewFragment`. Both tables carry a `user_id` and are queried by the current account.
- Wrong answers persist to SQLite (`ArithmeticDbHelper` + `ArithmeticRepository`, no Room/KSP). Four tables: `wrong_problems` (v1, deletable 查看错题), `rewards` (v2, created via `onUpgrade` when oldVersion < 2), `records` (v3, one row per question count: best score / best time / best combo — created when oldVersion < 3) and `wrong_history` (v4, append-only 历史错题). `insertReward` is called by the ViewModel when a reward is earned. Repository callbacks fire on a background executor: `startReviewRound` must `mainHandler.post { … }` back to the main thread before touching `LiveData` (setValue off-main-thread crashes 错题重练). At the end of a *practice* round (not 错题重练) the ViewModel calls `repository.updateRecord(count, score, seconds, bestCombo)`; the callback (posted to main thread) feeds `newRecord`, which shows "🎉 新纪录!" on the result page. Answering a wrong problem correctly during 错题重练 deletes that record via `repository.deleteWrong`. The 错题本 list (`ReviewFragment`) is a card-list — formula / 正确答案 / 你的答案 in aligned columns.
- 用户账号 (DB v5, `users` table + `user_id` on all four game tables): local-only accounts — no network. `AccountRepository` (`arithmetic/`) owns register/login/logout/session (`current_user_id` int in `app_prefs`; **id 0 = guest**, which also owns all pre-4-user data preserved by the v5 migration) and the avatar files (`filesDir/avatars/avatar_<id>.jpg`, staged as `_new_<ts>.jpg` then `renameTo`d on commit). Passwords are salted SHA-256 via `PasswordHasher` (pure Kotlin, unit-tested in `UserAccountTest`); `UserValidation` enforces username 2–20 chars and password 4–32 chars. All game-data reads/writes take a `userId` param (`recordWrong`/`deleteWrong`/`insertReward`/`updateRecord`/`fetchRecords`/`countRewards`/`fetchWrong`/`fetchHistory`); ViewModels/Fragments pass `AccountRepository.currentUserId()`, so guest and each account see isolated 错题/奖励/纪录. `records` PK is composite `(user_id, count)` — the v4→v5 `onUpgrade` renames the old `records` to `records_v4`, recreates it and copies legacy rows as user 0; game tables get `user_id INTEGER NOT NULL DEFAULT 0` via `ALTER TABLE`. UI: a setup-page account card (`img_current_avatar`/`text_current_user`/`text_current_user_hint`/`btn_settings` 设置) navigates to `nav_settings`; the settings page repeats that row as `img_settings_avatar`/`text_settings_user`/`btn_settings_account`, which opens `AccountBottomSheet` (a `BottomSheetDialogFragment`, layout `dialog_account.xml`) — guest form toggles 登录/注册 (`registerMode`), register lets you pick an avatar via `ActivityResultContracts.GetContent("image/*")`, logged-in view offers 修改头像/退出登录; `onAccountChanged` refreshes the settings row + setup row + `refreshRewardCounts()`. Avatars render through `AvatarUtil` into `ShapeableImageView` (`ShapeAppearance.App.Avatar` = 50% rounded).
- The 成就 page (`AchievementsFragment`/`AchievementsViewModel`, loaded by `loadRewardCounts`) shows all four reward counts, maps the crown count to a level via `RewardRules.levelIndexForCrowns` with a "next level needs N more crowns" line, and lists personal bests from `repository.fetchRecords` (`achievement_record_line`: count / full-score count / 用时 / 最高连击) — all scoped to the current account.
- Responsive layout variants exist under `layout-w600dp/` and `layout-w1240dp/` (legacy template chrome). When editing a layout, update all variants consistently.
